= Wager: relation ledger
Status: Stage 8. Each stage added its entries in the same commit as its rules, or in the commit of its records.
:toc: left
:sectnums:

This file lists each judgement form and each relation of the target calculus.
The baseline is the list in `docs/theory/00-notation.adoc`: kinding, conversion, the function `nf`, graded typing, trope transition.

Each entry has one class:

[cols="1,4",options="header"]
|===
| Class | Meaning
| baseline | The form is in 00-notation and is used as written there.
| baseline, changed | The form is in 00-notation. This experiment changes it. The change is named.
| specification only | The relation is used in theorem statements. No typing or kinding rule uses it.
| proof-internal | The relation is used in proofs only. No rule and no statement uses it.
| ADDED | The relation is not in 00-notation, and a typing or kinding rule uses it.
| source | The relation belongs to the source calculus (the fragment of System FC). The target calculus does not have it. It does not count against the wager.
|===

An ADDED entry counts against the wager. *Stages 1 to 5 and Stage 6, part 1 have no ADDED entry.*
Stage 6, part 2 has 2 entries with no class (R23, R24). The task says that the owner decides how they count.
The ledger has one "baseline, changed" entry for the target calculus (R1). The owner decides how it counts.
Stage 8 has no ADDED entry. It has one "baseline, changed" entry (R26): the typing judgement of the extension of Stage 8 has a context of type variables. The owner asked for this extension (DC-8.1), and the owner decides how it counts.

== Judgement forms of the target calculus

[cols="1,3,3,2,4",options="header"]
|===
| Id | Form (00-notation) | Agda identifier | Class | Notes

| R1
| `Γ ⊢ A : k` (kinding)
| `Ty Γ k` in `Wager.L1.Syntax` (simple kind, intrinsic) and `_⊢ᵏ_` in `Wager.L1.Kinding` (grades)
| baseline, changed
| The context of the kinding judgement is graded: `γ ⊢ᵏ A` has a usage vector γ for the type variables.
  The documents grade term contexts only. The task asks for this change (DC-1.3).
  The form is the same form. No new relation between types exists.

| R2
| `Γ ⊢ A ≡ B : k` (conversion)
| `DefEq` in `Wager.L1.Conversion`
| baseline
| β, equivalence, congruence, as in 02-l1-equality. No η.
  New rules of the same relation: the δ-rules of the signature primitives (DC-1.1). They are computation rules of total type-level functions.

| R3
| `nf(A)`
| `nf` in `Wager.L1.Eval`
| baseline
| A total function. `DefEq t u ↔ nf t ≡ nf u` is proved (`Wager.Proofs.l1-equality`).

| R4
| `Γ ⊢ᵣ t : A` (graded typing)
| `_▸_⊢_∶_` in `Wager.L2.Typing`
| baseline
| Declarative, with a subusage rule and a conversion rule.
  The only relation between types in a rule is `DefEq` (rule `t-conv`).

| R5
| `A@s ⟶ A@s'` (trope transition)
| The premise and the conclusion of rule `t-step`: `carrier o at from o` and `carrier o at to o`, from `Wager.L2.Signature.TSig`
| baseline
| It is not a separate inductive relation. The signature gives, for each operation, one carrier type and two states.
  The carrier type cannot change (DC-1.4). Thus an operation is never a cast between two different carrier types.
|===

== The extension of Stage 6, part 2 (the identity type)

*The 2 entries of this section have no class. The class is the decision of the owner.* The task says: "Do not decide whether option 1 adds a relation." The entries give the facts. `VERDICT.adoc` gives the trade.

EQUALITY EVIDENCE IS NOW A TERM (DC-6.5).

[cols="1,3,2,5",options="header"]
|===
| Id | Agda identifier | Class | Notes

| R23
| `_▸_⊢ⁱ_∶_` in `Wager.Identity.Typing`
| OWNER DECIDES
| The typing judgement of the target with the identity family. It has the form of R4 (`Γ ⊢ᵣ t : A` of 00-notation). It is a new Agda data type (DC-6.6), with the 12 rules of R4 and one more rule, `t-cast`.
  `γ ▸ Γ ⊢ⁱ e ∶ base (Id A B)` reads: in the context Γ, the term e is evidence that the closed types A and B are equal. A variable of the type `base (Id A B)` in Γ is a local equality assumption.
  The judgement thus does the work of a hypothetical equality. It has no new judgement form.

| R24
| `IdFamily` in `Wager.Identity.Family`
| OWNER DECIDES
| Not a relation in Agda. It is a record of signature entries: the base constants `Id A B`, the literals `rfl A`, and 3 laws.
  It is in this ledger because the family is conversion in the form of a type: for a closed term, the type `base (Id A B)` has a term exactly when `DefEq A B` holds (`T7-Intro`, `T7-Canonicity`).
|===

`keepⁱ` and `eraseⁱ` (`Wager.Identity.Term`) are functions. They are not relations.
The statements of T7, part 2 use the evaluation of untyped terms (R16) and observational equality (R18).

== Stage 8 (terms with open types)

Stage 8 is an extension in separate modules (`Wager/Poly`). No judgement and no relation of stages 1 to 7 changes.

[cols="1,3,2,5",options="header"]
|===
| Id | Agda identifier | Class | Notes

| R26
| `_▸_⊢ᵖ_∶_` in `Wager.Poly.Typing`
| baseline, changed
| The typing judgement for a term with open types. It has the form of R4 (`Γ ⊢ᵣ t : A` of 00-notation), and the types are in a context Δ of type variables. This is the change.
  It is a new Agda data type (DC-8.2), with the 12 rules of R4. No rule is new. The only relation between types in a rule is `DefEq` (rule `t-conv`), at the context Δ.
  R4 does not change. With no type variable, R26 gives R4 (`T8-Closed`).
  The owner asked for the extension (DC-8.1). The owner decides how the entry counts.

| R27
| `Coᵒ` in `Wager.Poly.Coercion`
| source
| Representational coercions between open source types. Each instance is a coercion of R14 (`_⟦_⟧ᶜ`). The target has no such relation: the translation of an open coercion is a term (`coerceᵒ`).

| R28
| `Agrees` in `Wager.Poly.Coercion`
| specification only
| A substitution of the target agrees with an instantiation of the source. It is a hypothesis of `T8-Type-Instance` and of `T8-Coercion-Instance`. No rule uses it.

| R29
| `TyTrᵖ`, `IsoTypedᵖ`, `SemTyᵖ`, `Nat`, `NatIso` in `Wager.Poly.CoercionProofs`
| proof-internal

`inst`, `⌊_⌋`, `⇑`, `Tᵒ`, `_⟦_⟧`, `coIᵒ`, `coerceᵒ`, `opsOf` and `opsOfᵖ` are functions. They are not relations.
The statements about the identity family (`T8-Evidence-Rigid`, `T8-Gadt-Not-Open`) use `DefEq` (R2) and no other relation.

== What is absent

* The target calculus has no coercion relation and no cast judgement. The coercion relation `Co` (R14) is in the source calculus only. The translation of Stage 4 makes each representational coercion a term of the target, with no new judgement.
* Representational equivalence exists as "specification only" (R11). It is not a judgement of the calculus.
* There is no subtyping relation between types.
* The extension of Stage 6, part 2 has no equality judgement with assumptions and no cast judgement. It has a term former (`cast`) and a rule of the typing judgement (R23).
* Stage 8 has no quantifier over types, no type abstraction and no type application. Instantiation is a function of Agda (`inst`). It is not a judgement.
