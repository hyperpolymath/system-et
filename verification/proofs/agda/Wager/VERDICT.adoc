== Answers of Stage 1

=== Are the laws enough for sums and `case`?

Yes, for the declarative judgement.
Rule `t-case` gives the two branches one usage vector, and rule `t-sub` raises each branch to that vector.
The rule has no join. T0 is proved with this rule.

The proofs of substitution and preservation use 14 of the 15 law fields. They do not use `le-antisym`.
The proof of progress uses no law.

A checker that computes a usage vector is a different matter.
For `case` it must find one vector that is above the two branch vectors.
The law set has no operation for this. This development has no such checker and proves nothing about one.

| F1
| The Lean class `GradeAlgebra` has 15 law fields and one derived law (`zero_add`). The documents say 16 laws.

| F2
| The systemet order of `Affine` has `0 ≤ ω` and `1 ≤ ω`, and `0` and `1` are not comparable.
  With this order a binder of grade `1` that is not used is rejected (`Wager.Examples.Stage1.T0-Affine.drop-rejected`).
  The grade `1` is thus linear, not affine. The anytype kernel uses the order `0 ≤ 1 ≤ ω`, which accepts the same term.

| F3
| T0 uses the law `a · 0 = 0` (`mul-zero`), in the product of a usage vector with a matrix.
  A structure that fails this law is outside T0. Stage 2 examines such a structure.

| F4
| The stock cubical v0.9 library forces `--guardedness` on each importer (DC-0.2).

| `scripts/check-proof-status.sh` fails on this branch, because the task forbids the marker line in `PROOF-STATUS.adoc`.
