== Installation steps (bash)

[source,bash]
----
mkdir -p /opt/agda/2.8.0/bin
curl -sSfL -O https://github.com/agda/agda/releases/download/v2.8.0/Agda-v2.8.0-linux.tar.xz
echo "824081b8dcbe431289a50ac6bd83e451f390c51c3884ac7a8c4a5c0df2632faf  Agda-v2.8.0-linux.tar.xz" | sha256sum -c -
tar -xJf Agda-v2.8.0-linux.tar.xz -C /opt/agda/2.8.0/bin
ln -sf /opt/agda/2.8.0/bin/agda /usr/local/bin/agda

git clone --depth 1 --branch v0.9 https://github.com/agda/cubical /opt/agda/cubical-0.9
git -C /opt/agda/cubical-0.9 rev-parse HEAD   # b150186d2544e7efeddd31e5d14a8b9ecbb100f7

mkdir -p "$(agda --print-agda-app-dir)"
echo "/opt/agda/cubical-0.9/cubical.agda-lib" >> "$(agda --print-agda-app-dir)/libraries"
----

The last command adds one line to the file `libraries`. It does not replace the libraries that a developer has there.

The project library file is `verification/proofs/agda/wager.agda-lib`.
It names the dependency `cubical-0.9` and has no `flags:` line.

== Flags

=== First line of each file

Each `.agda` file starts with this line:

[source,agda]
----
{-# OPTIONS --cubical --safe #-}
----

`scripts/check-proofs.sh agda` also passes `--safe` on the command line.

=== Finding: the stock library forces `--guardedness`

The `cubical.agda-lib` file of v0.9 has this line:

[source,text]
----
flags: --safe --cubical --no-import-sorts -WnoUnsupportedIndexedMatch --guardedness
----

Agda 2.8.0 rejects an import of a `--guardedness` module from a module that does not use the flag.
This is the error for a file that has only `--cubical --safe`:

[source,text]
----
error: [InfectiveImport]
Importing module Cubical.Foundations.Prelude using the
--guardedness flag from a module which does not.
----

Thus the rule "add `--guardedness` only in a file that needs coinduction" cannot hold with the stock library.
Stage 0 uses a second pragma line, `{-# OPTIONS --guardedness #-}`, in each file.
The owner accepted this on 2026-11-10 (see `DESIGN-CHOICES.adoc`, DC-0.2).

One alternative was tested.
A copy of the library tree with `--guardedness` removed from its `flags:` line lets a `--cubical --safe` file import `Cubical.Foundations.Prelude` and `Cubical.Data.List`.
That alternative changes the configuration of the pinned library.

=== Finding: `UnsupportedIndexedMatch`

The warning is on by default in Agda 2.8.0 (`agda --help=warning` marks it `d`).
It is not an error warning, and `--safe` accepts a file that has it.
The Agda 2.8.0 documentation says that a flagged definition "will not compute when applied to transports".

A test with intrinsically kinded syntax (`Var : Ctx → Kind → Type`) gave this result:

* A match that needs a constructor in an index (`Var (j ∷ Γ) k`, `Ty Γ ★`) gets the warning.
  The reason text is "It relies on injectivity of the data constructor".
* A match on a fully general index (`Ty Γ k`) gets no warning.
* The exit code is 0 in both cases.

The decision for this warning is in `DESIGN-CHOICES.adoc`, DC-0.3.
